# 1. Требования к системе

Перед началом установки необходимо убедиться, что оборудование или виртуальная машина соответствует приведенным ниже спецификациям. Несоблюдение минимальных требований может привести к крайне медленной работе приложения, частым ошибкам нехватки памяти или полной невозможности запуска.

## Минимальные требования (для разработки/тестирования)
Данный набор характеристик подходит исключительно для локального тестирования функционала одним или двумя пользователями, а также для демонстрации заказчику. Категорически не рекомендуется использовать такую конфигурацию в реальном рабочем окружении столовой.
- **Операционная система:** Windows 10/11 (рекомендуется для простоты администрирования), также совместимо с большинством современных дистрибутивов Linux (Ubuntu 20.04+, Debian 11+) и macOS.
- **Python:** Версия интерпретатора 3.10 или выше. Более старые версии не поддерживают синтаксис и функции, используемые в коде FastAPI.
- **Node.js:** Версия 18 и выше. Настоятельно рекомендуется использовать четные стабильные ветки (LTS). Версия 20+ предпочтительнее из-за улучшенной производительности сборщика Vite.
- **npm:** Версия 9 и выше. Обычно поставляется в комплекте с Node.js и обновляется автоматически при установке ноды.
- **RAM:** Минимум 4 ГБ оперативной памяти. Учтите, что часть памяти будет занята операционной системой, браузером и средствами разработки.
- **Диск:** Минимум 2 ГБ свободного места. Место необходимо для хранения исходного кода, виртуального окружения Python (содержит библиотеки) и папки `node_modules` (зависимости фронтенда, которая может занимать значительный объем).

## Рекомендуемые требования (для продакшена)
Для развертывания системы в локальной сети университета или на выделенном хостинге необходимо ориентироваться на следующие параметры. Они обеспечат быструю реакцию интерфейса при одновременной работе нескольких десятков или сотен студентов.
- **Python:** 3.12 или более новая версия. Новые версии Python содержат оптимизации скорости и исправления безопасности.
- **Node.js:** Версия 20+ (LTS). Сборка фронтенда на Vite выполняется значительно быстрее и стабильнее на актуальных версиях.
- **База данных:** PostgreSQL версии 15 или выше. PostgreSQL обеспечивает одновременную запись множества заказов без блокировок и позволяет делать потоковые бэкапы без остановки сервера.
- **RAM:** 8 ГБ. Дополнительная память позволит PostgreSQL эффективно кэшировать данные, а Uvicorn — держать несколько воркеров для обработки параллельных HTTP-запросов.
- **Диск:** Твердотельный накопитель (SSD). Скорость записи базы данных критична при пиковых нагрузках в обеденное время.

# 2. Установка программ

Процесс установки необходимого программного обеспечения является фундаментальным шагом. Все действия должны выполняться с правами администратора компьютера.

## 2.1 Установка Python

Python — это среда выполнения для бэкенд-части приложения. Мы будем использовать официальный установщик с веб-сайта Python Software Foundation.

1.  **Запуск браузера:** Откройте любой современный веб-обозреватель, будь то Google Chrome, Mozilla Firefox, Microsoft Edge или любой другой, который у вас установлен по умолчанию. Убедитесь, что у компьютера есть доступ в интернет.
2.  **Переход на официальный сайт:** В адресной строке браузера наберите адрес: `https://www.python.org/downloads/` и нажмите клавишу Enter. Переход по этой ссылке гарантирует, что вы скачаете дистрибутив без вирусов и посторонних встроек. Сторонние сайты-агрегаторы использовать настоятельно не рекомендуется.
3.  **Выбор версии:** Сайт автоматически определит вашу операционную систему и предложит большую желтую кнопку для скачивания последней стабильной версии, например, **Download Python 3.12.x**. Нажмите на эту кнопку левой кнопкой мыши. Обратите внимание, что точная цифра минорной версии (цифра после 3.12) не критична для работы UniFood.
4.  **Запуск установщика:** Дождитесь завершения загрузки файла с расширением `.exe`. Обычно загруженные файлы отображаются в нижней панели браузера или в системной папке «Загрузки». Найдите этот файл и дважды щелкните по нему для запуска. Если система безопасности Windows выдаст предупреждение о запуске приложения от неизвестного издателя, подтвердите свое намерение, нажав кнопку «Запустить» или «Да».
5.  **Критически важный шаг (PATH):** В открывшемся окне установщика Python, **прежде чем нажимать «Install Now»**, вы должны найти и поставить галочку в чекбоксе, который находится в самом низу окна. Текст рядом с ним гласит: `Add python.exe to PATH` или аналогичный на русском языке: `Добавить Python в PATH`. Этот шаг пропускать **запрещено**. Переменная окружения PATH позволяет операционной системе понимать команду `python` из любого места командной строки. Если галочку не поставить, вам придется каждый раз прописывать полный путь до исполняемого файла интерпретатора, что крайне неудобно и ведет к ошибкам в скриптах запуска.
6.  **Запуск установки:** После того как галочка установлена, смело нажимайте кнопку `Install Now`. При необходимости разрешите приложению вносить изменения на вашем устройстве в окне контроля учетных записей (UAC).
7.  **Ожидание и завершение:** Начнется процесс копирования файлов и настройки среды. Прогресс-бар будет постепенно заполняться зеленым цветом. Время установки зависит от скорости вашего диска и обычно занимает от 30 секунд до 2 минут. Дождитесь появления финального окна с надписью `Setup was successful`. После этого окно установщика можно закрыть.

## 2.2 Установка Node.js

Node.js необходим для работы фронтенда — то есть той красивой визуальной части, которую видят студенты и сотрудники столовой. Это среда выполнения JavaScript вне браузера, а также менеджер пакетов npm.

1.  **Переход на сайт:** Откройте браузер и перейдите по адресу `https://nodejs.org/`. Это единственный официальный источник дистрибутивов Node.js.
2.  **Выбор правильной версии:** На главной странице вы увидите две крупные зеленые кнопки. Левая кнопка предлагает версию с пометкой **LTS** (Long Term Support — Долгосрочная поддержка). Правая кнопка предлагает **Current** (Текущая новейшая версия с экспериментальными функциями). Для стабильной работы сервера UniFood **всегда выбирайте версию LTS**. На момент написания инструкции это версия 20.x или 22.x. Выбор версии Current может привести к несовместимости с некоторыми библиотеками фронтенда. Нажмите кнопку для скачивания LTS версии.
3.  **Запуск мастера установки:** Аналогично установке Python, найдите скачанный `.msi` или `.exe` файл в папке загрузок и запустите его двойным кликом.
4.  **Следование указаниям мастера:** Откроется стандартное окно мастера установки Windows. Процесс предельно прост и автоматизирован:
    - Нажмите кнопку `Next` (Далее) для начала установки.
    - Примите условия лицензионного соглашения, установив переключатель в положение «I accept the terms...» и нажав `Next`.
    - Выберите папку для установки. Настоятельно рекомендуется оставить путь по умолчанию (например, `C:\Program Files\nodejs\`), так как это упрощает дальнейшую диагностику проблем. Нажмите `Next`.
    - На странице выбора компонентов оставьте все галочки без изменений. В частности, убедитесь, что компонент **npm package manager** отмечен для установки. Нажмите `Next`.
    - Если появится страница с предложением установить дополнительные инструменты для компиляции нативных модулей (Tools for Native Modules), можете смело снимать галочку и нажимать `Next`. Для нашего проекта это не требуется.
    - Нажмите `Install` для запуска копирования файлов.
5.  **Завершение:** Дождитесь окончания процесса и нажмите `Finish`. После установки иногда требуется перезагрузка компьютера для корректного обновления переменных окружения, но в большинстве случаев этого не требуется.

## 2.3 Установка Git (необязательно, но полезно)

Git — это распределенная система контроля версий. Она не требуется для запуска уже готового архива с проектом, но она абсолютно незаменима, если вы планируете получать обновления от разработчиков через интернет, не скачивая каждый раз полный архив заново.

1.  **Переход на сайт:** Откройте браузер и введите `https://git-scm.com/downloads`.
2.  **Скачивание:** Сайт автоматически предложит установщик для вашей ОС (Windows). Нажмите на ссылку для скачивания.
3.  **Процесс установки:** Запустите скачанный файл. Мастер установки Git довольно длинный и содержит множество настроек. Для целей администрирования UniFood подойдут **стандартные настройки по умолчанию**. Вы можете просто нажимать кнопку `Next` на всех этапах, вплоть до финального `Install`. Единственное, на что стоит обратить внимание — на этапе выбора редактора по умолчанию, можно оставить Vim, но если вы не знакомы с ним, удобнее выбрать Nano или Notepad++ из выпадающего списка. Это влияет только на написание сообщений коммитов и не сказывается на работе проекта.

## 2.4 Проверка установки

После того как все компоненты были установлены, необходимо выполнить проверку, чтобы убедиться, что операционная система их "видит".

**Откройте терминал (командную строку):**

- Нажмите комбинацию клавиш `Win + R` (кнопка с логотипом Windows и английская буква R).
- В появившемся небольшом окне «Выполнить» напечатайте слово `cmd`.
- Нажмите клавишу `Enter` или кнопку «ОК». Откроется черное окно с мигающим курсором — это интерфейс командной строки.

**Введите последовательно следующие команды, нажимая Enter после каждой:**

```bash
python --version
node --version
npm --version
```

**Анализ результатов:**
- Команда `python --version` должна вывести строку вроде `Python 3.12.3`. Если вы видите ошибку `"python" не является внутренней или внешней командой...`, это означает, что либо вы не поставили галочку `Add to PATH` при установке, либо требуется перезагрузка компьютера.
- Команда `node --version` должна вывести версию, например `v20.11.0`.
- Команда `npm --version` также покажет цифры, например `10.2.4`.

Если все три команды отобразили корректные номера версий без сообщений об ошибках — подготовительный этап завершен успешно, и можно переходить к работе с файлами проекта.

# 3. Подготовка проекта

Теперь мы переходим к непосредственному развертыванию файлов сервиса UniFood и настройке его окружения.

## 3.1 Распаковка проекта

Вы должны были получить от разработчиков или загрузить с сервера архив с именем, например, `unifood-mvp-v1.zip`. Этот архив необходимо извлечь в удобное место на жестком диске.

1.  **Создание рабочей папки:** Рекомендуется создать папку в корне диска `C:`, чтобы избежать проблем с длинными путями к файлам и правами доступа на запись. Например: `C:\Projects\`.
2.  **Копирование архива:** Переместите или скопируйте файл архива в папку `C:\Projects\`.
3.  **Распаковка:** Щелкните правой кнопкой мыши по файлу архива (например, `unifood.zip`). В контекстном меню выберите пункт «Извлечь все...» или воспользуйтесь архиватором (WinRAR, 7-Zip). В качестве пути для извлечения укажите `C:\Projects\`. В результате будет создана папка `C:\Projects\UniFood\`. Убедитесь, что внутри папки `UniFood` находятся папки `backend` и `frontend`, а не еще одна вложенная папка `UniFood`.

**Ожидаемая структура каталогов (важно проверить глазами):**


## 3.2 Создание виртуального окружения (Python Virtual Environment)

Виртуальное окружение — это изолированный "контейнер" для библиотек Python. Он необходим для того, чтобы разные проекты на вашем компьютере не конфликтовали друг с другом из-за разных версий одних и тех же библиотек. Например, один проект может требовать версию SQLAlchemy 1.4, а UniFood требует 2.0. Виртуальное окружение решает эту проблему.

**Выполните следующие команды в терминале (командной строке):**

Сначала перейдем в папку `backend`:
```bash
cd C:\Projects\UniFood\backend
```
*Пояснение:* Команда `cd` означает "Change Directory" (сменить директорию). Мы перемещаем курсор командной строки в нужное нам место.

Теперь создадим само окружение командой:
```bash
py -m venv venv
```
*Разбор команды:*
- `py` — это лаунчер Python на Windows, он автоматически находит последнюю установленную версию Python.
- `-m venv` — говорит лаунчеру запустить встроенный модуль `venv` (virtual environment).
- `venv` — это имя папки, которая будет создана в текущей директории. Внутри нее будет храниться копия интерпретатора Python и все скачанные библиотеки. Имя папки может быть любым, но `venv` является стандартом де-факто.

**Активация окружения:**

После создания папки `venv`, её нужно активировать, чтобы консоль "понимала", что мы работаем именно в этом изолированном пространстве.
```bash
venv\Scripts\activate
```
- На Windows путь к скрипту активации находится в подпапке `Scripts` внутри папки `venv`.

**Проверка успешной активации:**
Если вы всё сделали правильно, в самом начале строки приглашения командной строки появится префикс `(venv)`. Это визуальный индикатор того, что виртуальное окружение активно. Пример того, как это выглядит:
`(venv) C:\Projects\UniFood\backend>`

## 3.3 Установка зависимостей Backend (Python)

Когда виртуальное окружение активно, мы можем безопасно устанавливать пакеты, перечисленные в файле `requirements.txt`. Этот файл содержит точные названия и версии библиотек, которые проверены разработчиками на совместимость.

Убедитесь, что вы всё еще находитесь в папке `C:\Projects\UniFood\backend` и префикс `(venv)` отображается. Затем выполните команду:

```bash
py -m pip install -r requirements.txt
```

*Что происходит:* Менеджер пакетов `pip` считывает файл `requirements.txt`, подключается к официальному репозиторию PyPI (Python Package Index) и скачивает каждую библиотеку в папку `venv\Lib\site-packages`. Процесс может занять несколько минут в зависимости от скорости вашего интернета. На экране будут бежать строки с прогресс-барами.

### ВАЖНО: Содержимое файла `requirements.txt` (для справки)

Администратору полезно знать, какие ключевые библиотеки используются в проекте и за что они отвечают:

```
fastapi==0.135.3           # Современный веб-фреймворк для создания API
uvicorn[standard]==0.34.0  # Молниеносный ASGI-сервер для запуска FastAPI
sqlalchemy==2.0.38         # Мощный ORM (Object Relational Mapper) для работы с БД
```

# 4. Настройка конфигурации

Самая ответственная часть, где администратор вносит уникальные параметры конкретной инсталляции UniFood.

## 4.1 Конфигурационный файл Backend (.env)

Файл `.env` (сокращение от "environment") хранит настройки в виде простых пар `КЛЮЧ=ЗНАЧЕНИЕ`. Это сделано для того, чтобы не хранить пароли и секретные ключи прямо в коде программы.

1.  **Откройте проводник** и перейдите в папку: `C:\Projects\UniFood\backend\`.
2.  **Создайте новый текстовый файл** (Правая кнопка мыши -> Создать -> Текстовый документ).
3.  **Назовите его** строго `.env` (именно с точкой в начале и без расширения .txt). Windows может ругаться на отсутствие имени файла, просто согласитесь с переименованием. Если файл стал невидимым, значит у вас скрыты системные файлы — это нормально. Чтобы редактировать его, откройте его через Блокнот (Notepad) или, что гораздо лучше, через редактор кода Notepad++ или VS Code.
4.  **Заполните файл** следующим содержимым, заменив значение в строке `SECRET_KEY` на свое:

```env
DATABASE_URL=postgresql:///./unifood.db
SECRET_KEY=ВАШ_СЕКРЕТНЫЙ_КЛЮЧ_СЮДА_ВСТАВИТЬ
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=30
```

**Что означает каждая строка:**
- `DATABASE_URL`: Строка подключения к базе данных. `postgresql:///./unifood.db`
- `SECRET_KEY`: Это строка символов, используемая для цифровой подписи JWT-токенов авторизации. Если злоумышленник узнает этот ключ, он сможет подделывать токены и получать доступ к админ-панели от имени любого пользователя.
- `ALGORITHM`: Алгоритм хеширования для подписи. `HS256` — это промышленный стандарт.
- `ACCESS_TOKEN_EXPIRE_MINUTES`: Время жизни токена доступа в минутах. По истечении 30 минут бездействия пользователя система попросит залогиниться заново (это мера безопасности).

## Генерация надежного SECRET_KEY

Ни в коем случае не оставляйте значение `ВАШ_СЕКРЕТНЫЙ_КЛЮЧ` или простые слова вроде `password123`! Это первое, что попробует подобрать взломщик. Сгенерируйте криптостойкую случайную строку с помощью встроенного модуля Python.

Вернитесь в первое окно терминала (где активировано виртуальное окружение `(venv)`) и выполните:

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

**Расшифровка команды:** Эта однострочная программа на Python импортирует модуль `secrets`, вызывает функцию генерации безопасного токена длиной 32 байта в формате URL-safe Base64 и выводит результат на экран.
Вы увидите строку похожую на: `LBe8qZx9Vn7mP2rF5jU3tG6yH1kN4sW8`.

Скопируйте эту строку целиком, откройте файл `.env` в Блокноте и вставьте её после знака `=`, заменив текст `ВАШ_СЕКРЕТНЫЙ_КЛЮЧ_СЮДА_ВСТАВИТЬ`. Сохраните файл (`Ctrl+S`).

## 4.2 Конфигурационный файл Frontend (.env)

Чтобы фронтенд знал, на каком порту и адресе искать работающий сервер FastAPI, ему тоже нужен свой файл `.env`.

1.  **Перейдите в папку фронтенда:** `C:\Projects\UniFood\frontend\unifood-frontend\`.
2.  **Создайте файл с именем `.env`** аналогичным способом (без расширения, через Блокнот).
3.  **Вставьте в него следующую строку:**

```env
VITE_API_URL=http://localhost:8001
```

- **Почему именно так?** Переменные окружения для сборщика Vite обязательно должны начинаться с префикса `VITE_`, иначе они не будут доступны в коде React.
- **Значение `http://localhost:8001`:** Это адрес и порт, на котором мы будем запускать бэкенд в следующих шагах. Порт 8001 выбран вместо стандартного 8000, чтобы избежать конфликтов с другими возможными сервисами на компьютере.

## 4.3 Создание структуры базы данных (Миграция)

# 5. Запуск проекта

Мы подошли к самому волнующему моменту — первому запуску системы. Для работы UniFood необходимо, чтобы оба процесса — Backend (сервер API) и Frontend (сервер разработки Vite) — работали одновременно. Держите открытыми два терминала.

## 5.1 Запуск Backend (FastAPI + Uvicorn)

В **первом терминале** (где активировано виртуальное окружение `(venv)`):

1.  **Убедитесь, что вы в папке `backend`.** При необходимости выполните `cd C:\Projects\UniFood\backend`.
2.  **Активируйте окружение, если оно не активно** (`venv\Scripts\activate`).
3.  **Запустите сервер командой:**

```bash
py -m uvicorn app.main:app --reload --port 8001
```

**Подробное объяснение аргументов:**
- `py -m uvicorn`: Запуск модуля Uvicorn как исполняемого скрипта Python.
- `app.main:app`: Указание на то, где находится объект приложения FastAPI. `app.main` — это путь к файлу `main.py` внутри папки `app`, а через двоеточие указано имя переменной (`app`), которая создается в этом файле строкой `app = FastAPI()`.
- `--reload`: **Режим разработчика.** При включении этого флага Uvicorn будет следить за изменениями в файлах проекта. Как только вы измените и сохраните `.py` файл, сервер автоматически перезагрузится. Это невероятно удобно при доработках, но **в продакшене этот флаг должен быть убран**.
- `--port 8001`: Явное указание сетевого порта, который будет слушать сервер.

**Что вы увидите:** В терминале появится логотип FastAPI и Uvicorn, а затем строки:
```
INFO:     Will watch for changes in these directories: ['C:\\Projects\\UniFood\\backend']
INFO:     Uvicorn running on http://127.0.0.1:8001
INFO:     Application startup complete.
```

**Способы проверки работоспособности:**
1.  Откройте браузер и перейдите по адресу `http://localhost:8001/docs`. Если вы видите красивую страницу с заголовком "FastAPI" и списком эндпоинтов (Swagger UI) — сервер работает и полностью готов принимать запросы.
2.  Перейдите по адресу `http://localhost:8001/health`. Вы должны увидеть простой JSON-ответ: `{"status": "healthy"}`. Это встроенный эндпоинт мониторинга состояния сервера.

# 9. Резервное копирование и восстановление данных

Без резервного копирования (бэкапа) любое администрирование теряет смысл. Сбой жесткого диска, случайное удаление файла или вирус-шифровальщик могут мгновенно остановить работу столовой. Инструкция ниже описывает самый простой и надежный способ — создание копии папки с проектом и файла базы данных средствами Windows.

## 9.1 Ручное создание резервной копии через BAT-файл

Вместо того чтобы каждый раз вручную копировать папки мышкой, мы создадим простой исполняемый сценарий (скрипт), который сделает всё сам.

**Пошаговое создание скрипта `backup.bat`:**

1.  Откройте любую папку, где вам удобно хранить утилиты, например `C:\Projects\UniFood\`.
2.  Нажмите правой кнопкой мыши -> Создать -> Текстовый документ.
3.  Переименуйте файл из `Новый текстовый документ.txt` в `backup.bat`. Система спросит: «После изменения расширения этот файл может оказаться недоступным. Изменить?» — нажмите **Да**.
4.  Нажмите на файле `backup.bat` правой кнопкой мыши и выберите «Изменить» (или «Открыть с помощью» -> «Блокнот»).
5.  **Скопируйте и вставьте** в открывшийся Блокнот следующий текст точно как он есть:

```batch
@echo off
:: Скрипт резервного копирования UniFood
:: Автоматически создает папку с текущей датой и копирует туда БД и файлы проекта

:: Получаем текущую дату в формате ГГГГ-ММ-ДД
set DATE=%date:~-4,4%-%date:~-7,2%-%date:~-10,2%

:: Создаем целевую папку для бэкапа. Если такой папки нет - создаем.
mkdir "C:\Backups\UniFood\%DATE%"

:: Копируем файл базы данных PostgreSQL. Это самое ценное!
copy "C:\Projects\UniFood\backend\unifood.db" "C:\Backups\UniFood\%DATE%\unifood.db"

:: Копируем весь каталог проекта, включая подпапки и скрытые файлы (/E /H /C /I)
:: Это на случай, если нужно откатить не только БД, но и код
xcopy "C:\Projects\UniFood" "C:\Backups\UniFood\%DATE%\UniFood\" /E /H /C /I

echo.
echo ============================================
echo Резервная копия успешно создана!
echo Дата копии: %DATE%
echo Папка назначения: C:\Backups\UniFood\%DATE%
echo ============================================
pause
```

**Объяснение синтаксиса:** Символ `::` в начале строки означает комментарий, он не выполняется. Строка `set DATE` — это хитрый способ выделить год, месяц и день из системной переменной Windows.

6.  **Сохраните файл** (Файл -> Сохранить или `Ctrl+S`). Закройте Блокнот.

**Проверка работы скрипта:**
- Дважды щелкните по файлу `backup.bat`. Откроется черное окно командной строки, побегут строки копирования файлов.
- В конце появится надпись "Резервная копия успешно создана!" и предложение нажать любую клавишу.
- Откройте папку `C:\Backups\UniFood\` и убедитесь, что там появилась подпапка с сегодняшней датой (например, `2026-04-09`), а внутри нее лежит файл `unifood.db` и папка `UniFood`.

## 9.2 Настройка автоматического резервного копирования (Планировщик задач Windows)

Ручной запуск хорош, но человеку свойственно забывать. Настроим автоматическое создание бэкапа каждый вечер.

1.  Нажмите кнопку «Пуск» и начните вводить слово **«Планировщик заданий»** (или Task Scheduler). Запустите найденное приложение.
2.  В правой колонке окна планировщика нажмите ссылку **«Создать простую задачу...»**.
3.  **Имя задачи:** Введите понятное название, например `UniFood Daily Backup`. Нажмите «Далее».
4.  **Триггер:** Выберите периодичность **«Ежедневно»**. Нажмите «Далее».
5.  **Время:** Укажите время, когда сервер точно никто не использует, но компьютер включен. Например, **23:00**. Оставьте повтор каждые 1 день. Нажмите «Далее».
6.  **Действие:** Выберите **«Запустить программу»**. Нажмите «Далее».
7.  **Программа или сценарий:** Нажмите кнопку «Обзор...» и найдите на диске ваш файл `C:\Projects\UniFood\backup.bat`. Выберите его.
8.  **Рабочая папка:** (Можно оставить пустой).
9.  **Завершение:** Нажмите «Готово». Задача создана. Система будет запускать скрипт бэкапа каждый день в 23:00, даже если вы забыли о нем.

## 9.3 Процедура восстановления из резервной копии

Предположим, что база данных повреждена или администратор случайно удалил все заказы. Чтобы всё вернуть, выполните следующие действия:

1.  **Остановите сервер.** Перейдите в оба терминала, где запущены Backend и Frontend, и нажмите комбинацию клавиш `Ctrl + C` (зажать Ctrl и нажать C один раз). Это корректно завершит работу приложений.
2.  **Найдите нужную резервную копию.** Откройте папку `C:\Backups\UniFood\`. Выберите подпапку с датой, на состояние которой вы хотите откатиться (обычно берут вчерашнюю или позавчерашнюю копию).
3.  **Скопируйте файл базы данных.** Зайдите в выбранную папку (например, `2026-04-08`), найдите файл `unifood.db`, скопируйте его (`Ctrl+C`).
4.  **Вставьте файл с заменой.** Перейдите в рабочую папку проекта `C:\Projects\UniFood\backend\`. Вставьте скопированный файл (`Ctrl+V`). Система спросит: «Заменить файл в папке назначения?». Ответьте **«Заменить файл в папке назначения»**.
5.  **Запустите сервер заново** согласно разделу **5.1**.
6.  **Проверьте работу.** Зайдите в админ-панель. Данные о пользователях и заказах должны соответствовать состоянию на момент создания бэкапа.

# 10. Рекомендации по развертыванию в продакшен (Production Mode)

Система, которую вы запустили, работает в так называемом **режиме разработки**. Это значит, что сервер выводит много отладочной информации, а фронтенд подгружает файлы по частям, что удобно для исправления ошибок, но неэффективно для скорости работы и потребления ресурсов. Когда вы будете готовы перевести столовую на полноценную работу, необходимо выполнить ряд шагов по оптимизации.

**Что необходимо изменить:**

- **Использование Nginx в качестве обратного прокси:** Сейчас студенты подключаются к порту `8001` напрямую к Uvicorn. В продакшене перед Uvicorn ставят веб-сервер Nginx. Он берет на себя раздачу статических файлов (картинок меню, иконок), сжатие ответов и, что самое важное, **защиту от DDoS атак и медленных клиентов**.
- **Настройка HTTPS (SSL-сертификат):** Передача паролей в открытом виде по HTTP внутри даже локальной сети небезопасна. Можно использовать самоподписанный сертификат для внутренней сети вуза или бесплатный сертификат Let's Encrypt, если сервер имеет белый IP-адрес. Это гарантирует, что пароль `admin123` не сможет перехватить студент с ноутбуком, сидящий в той же Wi-Fi сети.
- **Запуск Backend без флага `--reload`:** Флаг `--reload` заставляет Uvicorn постоянно опрашивать файловую систему на предмет изменений, что создает лишнюю нагрузку на диск. В продакшене запуск производится командой `py -m uvicorn app.main:app --host 0.0.0.0 --port 8001 --workers 4` (где `workers 4` создает 4 параллельных процесса для обработки запросов).

# 11. Процедура обновления системы (Update Policy)

Разработчики UniFood могут выпускать новые версии с исправлением ошибок или добавлением новых функций. Обновление нужно проводить аккуратно, так как оно может затронуть структуру базы данных.

**Стандартный алгоритм обновления:**

1.  **Остановка сервера:** Нажмите `Ctrl+C` в обоих терминалах, чтобы остановить Backend и Frontend.
2.  **Создание полного бэкапа:** **Обязательно!** Запустите файл `backup.bat` вручную, чтобы создать точку восстановления перед внесением изменений. Убедитесь, что копия создалась.
3.  **Замена файлов:** Разработчик предоставит вам новый архив. Извлеките его содержимое с заменой старых файлов в папке `C:\Projects\UniFood\`. **Внимание:** Файл `.env` заменять не нужно, если разработчик не попросил об этом специально, иначе сотрутся ваши настройки подключения к БД и секретный ключ.
4.  **Обновление зависимостей:** Перейдите в терминал бэкенда, активируйте виртуальное окружение и снова выполните `py -m pip install -r requirements.txt`. Аналогично для фронтенда выполните `npm install` в папке фронтенда. Новые версии кода могли потребовать новые версии библиотек.
5.  **Применение миграций БД:** Это критически важный шаг. Выполните скрипт миграции, указанный разработчиком в примечании к релизу (например, `py -m app.migrate_add_promo_codes`). Если этого не сделать, приложение упадет с ошибкой, так как будет искать в базе данных столбцы, которых там нет.
6.  **Запуск сервера:** Запустите бэкенд и фронтенд как обычно.
7.  **Тестирование:** Войдите в админ-панель и попробуйте создать тестовый заказ. Убедитесь, что все кнопки нажимаются.

# 12. Часто встречающиеся ошибки и их устранение (Troubleshooting)

В работе любого программного обеспечения возникают нештатные ситуации. Ниже приведена таблица-шпаргалка для администратора на случай, если что-то пошло не так.

| Ошибка / Симптом | Вероятная причина | Решение / Что делать |
| :--- | :--- | :--- |
| **ModuleNotFoundError: No module named 'fastapi'** | Не установлены зависимости Python или виртуальное окружение не активировано. | Убедитесь, что в терминале есть префикс `(venv)`. Если его нет, выполните `venv\Scripts\activate`. Затем повторно выполните `pip install -r requirements.txt`. |
| **Ошибка при npm install: '... not accessible from ...'** | Ошибка прав доступа или блокировка антивирусом. | Попробуйте удалить папку `node_modules` и файл `package-lock.json`, затем повторить `npm install`. Если не помогает, запустите терминал от имени Администратора. |
| **Порт 8001 уже используется (Address already in use)** | Другая копия сервера уже запущена или порт занят другой программой (например, Skype). | 1. Найдите окно с уже запущенным сервером и остановите его. <br> 2. Либо поменяйте порт запуска в команде на `--port 8005` (и не забудьте поправить `.env` фронтенда). |
| **Frontend открывается, но вместо меню белый экран и ошибки в консоли (F12)** | Неверный `VITE_API_URL` в файле `.env` фронтенда или бэкенд не запущен на порту 8001. | Проверьте, открывается ли ссылка `http://localhost:8001/health` в браузере. Если нет — бэкенд упал. Запустите его заново. |
| **При входе пишет "Invalid credentials" (неверные данные)** | 1. Неправильно введен email/пароль. <br> 2. Слетела база данных (файл `unifood.db` пустой). | 1. Проверьте раскладку клавиатуры и Caps Lock. <br> 2. Запустите скрипт `py -m app.create_sample_data` для повторного создания админа. |
| **JWT ошибка (Could not validate credentials)** | В файле `.env` бэкенда изменено значение `SECRET_KEY` после того, как пользователи уже были созданы. | Токены, выданные со старым ключом, стали недействительны. Это нормально. Нужно просто заново войти в систему (выйти из аккаунта и войти). |
